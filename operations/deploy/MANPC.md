# MANPC verification (Windows)

The Windows task is opt-in and runs as the current logged-in user; no stored password, elevated token, desktop automation, or console window. The single VPS owner still submits saves and consumes verified receipts. The scheduled task handles existing capture URLs only, does not poll uncaptured job IDs, and waits when the owner receipt is stale or in a provider recovery/blocked state. Archive response 401/429/5xx stops the current run; Retry-After is honored, with a 30-minute floor. Maximum three rotating candidates per half-hour, eight MiB per fetched body, a ten-minute scheduler runtime limit and IgnoreNew concurrency. Larger files remain with the existing VPS workflow. No URLs or provider exception text are stored in local operator logs.

Use the exact tested `operations/manpc_task.py`, the existing compatible wiki verification modules and `pythonw.exe`. Run `install-manpc-task.ps1` with absolute paths to those and a dedicated state directory. The script refuses to replace an existing task. A scheduled task can run while the PC is logged in and the desktop is locked; it cannot verify when the PC is off, sleeping, or logged out. It catches up after missed runs when available. It does not wake a sleeping PC or create a background service.

Inspect `SWCCG MANPC Verification` in Windows Task Scheduler: Run, End, Disable, Enable, Properties and History. Local `status.json`, `runs.log` and at most one rotated `runs.previous.log` are readable without an AI. Last-run result zero means the wrapper completed or respected a hold, not proof of a new capture. The private dashboard shows the last received heartbeat, a projected next run, last successful batch, accepted ledger verification counts and an error count. A stale heartbeat means offline, disabled or unable to reach the VPS; not proof that the computer itself is off.

If the task misbehaves, End then Disable it; re-enable manually after correcting the problem. Do not delete the state folder or owner inbox records. No change to archive credentials, transfer of a browser profile, second saver, public HTTP route or change to shared cooldown ownership is needed.
